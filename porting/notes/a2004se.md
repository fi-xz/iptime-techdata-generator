# A2004SE (RTL8197F + 외장 RTL8367 계열 스위치) 포팅 정찰 노트

> 출처: 사용자 조사 노트 (2026-11) + 순정 펌웨어 `a2004se_ml_16_006.bin` 정적 분석 (2026-11-07).
> 같은 RTL8197F + rtl8367r 조합 모델(A2004MU, AX2004T, AX1500SR, A2003NS-MU, A2004NS-MU 등)에도 참고용.

## 0. 1차 목표와 범위

- 1차 목표: **유선 전용 OpenWrt** (initramfs 부팅 → 쉘 → 이더넷). 무선은 범위 밖.
- 이 단계에서는 드라이버를 새로 쓰지 않는다. 정찰, 레퍼런스 비교, 문서화만 한다.
- RTL8812F(5GHz)에는 upstream 드라이버 경로가 없다 (Realtek 메인테이너 회신, 2026-11). 그래서 후보표에서는 "머지 가능성 낮음"으로 표시된다.
  이 표시는 **무선 포함 upstream 머지** 기준이다. 1차 유선 목표에는 영향이 없다.

### 이전 메모의 정정

- A2004SE는 **Wi-Fi 6 모델이 아니다.** 5GHz는 11ac 2x2(80MHz) **RTL8812FR**이다 (순정 SI `chipset.wl[5g]`).
- AX2004T와 AX1500SR은 같은 SoC와 스위치를 쓰는 **11ax 모델**(5GHz=RTL8832BR)이다. 무선 쪽은 A2004SE와 다르다.
  다만 유선 경로(97F + 8367 계열 + 플래시 레이아웃)는 거의 같다.
- `iptime-gpl/userapps_a2004sr` 미러(2.6.30, 97D/RLX5281)는 A2004SE 커널과 무관하다. `rtlac_97f_config`와 `mkdefs.97f` 이름만 단서다.

| 항목 | 값 |

| 5GHz | RTL8812FR, 11ac 2x2 80MHz, PCIe |

| 보드명 | IP04382 (**A2004MU와 같은 보드명**. 다만 A2004MU는 64MB/8MB이고 GPIO도 달라서 같은 PCB 리비전은 아님) |

GPIO (A2004SE)

| 기능 | 핀 | active |
|---|---:|---|
| CPU LED | 57 | high |
| 리셋 버튼 | 36 | low |

## 2. 순정 펌웨어 (ml_16_006) 정적 분석

- 커널: `Linux version 3.10.90 ... (Realtek MSDK-4.4.7 Build 2001)`, 빌드 2026-05-15.
  → 미러에 있던 `mkdefs.97f`(USE_KERNEL_3_X, msdk-4.4.7)와 맞는 **Realtek SDK 3.4.x 계열 3.10 커널**이다.
  (참고: AX2004T와 AX1500SR은 커널 4.4이고, 무선은 `rtk_wifi6.ko`로 따로 들어간다.)
- 무선은 모듈이 아니라 **커널에 내장**된 `rtl8192cd`다. `.ko` 파일이 없다.
  8812F, 8822B, 8822C, 97F의 PHY/RF/AGC/TXPWR 테이블 이름이 문자열로 남아 있다 (`PHY_REG_8812F`, `RadioA_8812Fmp`, `TXPWR_LMT_8812Fmp_*`, `[97F] RFE type 0/3`).
  하드웨어 판별 문자열 `Hardware type = RTL8812FE/RTL8812FS`와 `found 8812F !!!`도 있다.
- 이더넷: `drivers/net/rtl819x/rtl819x_swNic.c` 계열이다 (Probing RTL819X NIC). 미러의 `drivers/net/rtl819x/`와 구조가 같다.
- 스위치 제어 플랫폼 장치: `rtl819x_8367r_reset_pin`, `rtl819x_8367r_i2c_pin`. GPIO 이름 `smi_SCK`, `smi_SDA`, `smi_RST`.
  → GPIO 비트뱅 SMI다. 핀 번호는 문자열로 나오지 않아서 플랫폼 데이터를 디스어셈하거나 실기에서 확인해야 한다.
- 스위치 초기화 시퀀스 (문자열 순서):
  `rtk_port_rgmiiDelayExt_set(r8367_cpu_port, TX_DELAY, RX_DELAY)` → `rtk_port_macForceLinkExt_set` → `rtk_cpu_enable_set(ENABLED)`
  → `rtk_cpu_tagPort_set(r8367_cpu_port, CPU_INSERT_TO_NONE)` → LED 그룹 설정 → `rtk_switch_maxPktLen_set(MAXPKTLEN_16000B)` → VLAN/PVID(WAN_VID).
  SSC를 켜는 지연 변형(`TX_DELAY_ENABLE_SSC`)도 따로 있다.
- PCIe: `Find PCIE Port, Device:Vender ID=%x`, `PCIE -> Cannot LinkUP`. 부트 중 5GHz 칩의 PCI ID를 출력할 가능성이 있다 → UART 로그로 확인.

## 3. 스위치 칩 식별 (미확정)

- 순정 SI 명세는 `chipset.eswitch.name=rtl8367r`이다. 하지만 이 값은 97F 계열 전 모델에 공통으로 붙는 **일반 표기**다.
- 커널에 `Switch v1.4 API: switchChip= %s`와 칩 문자열 `8367C`, `8370B`, `8364B`, `8363SC_VB`, `8367D`가 있다.
  → Realtek 통합 API v1.4가 **런타임에 칩을 판별**한다. 그래서 펌웨어만으로는 실제 칩을 알 수 없다. 부트로그 `switchChip=`이 결정적인 단서다.
- `dal_rtl8367c_*`, `dal_rtl8367d_*` 두 DAL이 모두 링크되어 있다. OCP PHY 접근에는 `rtl8367b_getAsicPHYOCPReg`(구 8367B 헬퍼)를 쓴다.
- 전작 A2004MU는 RTL8367RB-VB(chip_id 0x6367, ver 0x0020)로 추정되고, 구형 API v1.2.12를 쓴다.
- 0x6367은 RTL8365MB-VC(0x0040), RTL8367S(0x00A0), RTL8367SB(0x0010), RTL8367RB-VB(0x0020)가 공유하는 ID다 → chip_ver까지 읽어야 확정된다.
  (추정: 8367C API의 "8367C"는 RTL8367S/SB/RB-VB가 속한 세대 이름이다. 8367C로 판별되면 메인라인 지원 가능성이 높다.)
- 8367D로 판별되면 메인라인 rtl8365mb에 없을 가능성이 높다 (chip_id 미확인).

## 4. 메인라인 지원 현황 (Linux v7.4-rc1 기준)

- `drivers/net/dsa/realtek/rtl8365mb_main.c`의 `rtl8365mb_chip_infos[]`에는 0x6367 계열 4종만 등록되어 있다. RTL8367RB-VB는 지원된다.
- extint 1(port 6)과 extint 2(port 7)에서 RGMII를 쓸 수 있다. 벤더 코드는 EXT_PORT_1을 호스트로 쓰므로 extint 1(port 6)에 대응할 것으로 추정한다.
- 관리 버스: 메인라인 `realtek-smi`(GPIO 비트뱅) 바인딩으로 순정의 smi_SCK/SDA/RST를 그대로 받을 수 있다.

## 5. 가장 큰 위험: CPU 태그

- rtl8365mb는 CPU 태그가 필수다 (`rtl8_4`: SA 뒤 8바이트, `rtl8_4t`: 트레일러, EtherType 0x8899).
- 순정 SE 펌웨어는 `rtk_cpu_tagPort_set(..., CPU_INSERT_TO_NONE)`으로 태그를 끄고 VLAN/EFID로 LAN/WAN을 나눠 eth0/eth1로 쓴다.
- 97F 스위치 코어(conduit)가 0x8899 태그 프레임을 CPU↔P0 사이에서 변형 없이 통과시키는지는 검증하지 않았다.
  관련 후보: 97F `P0GMIICR`의 `CFG_CPUC_TAG`(bit25), `CFG_TX_CPUC_TAG`(bit26), `MACCR1.PORT0_ROUTER_MODE`. `rtl8_4t`(트레일러)가 우회책이 될 수 있다.

## 6. 연결 파라미터

- RGMII 지연: 레퍼런스 97F 보드는 8367 쪽 TX 0 / RX 5, 97F 쪽 TX 0 / RX 5다. SE의 실제 값은 미확인이다 (`rtk_port_rgmiiDelayExt_set` 인자를 디스어셈해서 확인).
- 벤더 드라이버는 97F 전용 EMI 레지스터(0x13C3…0x1d5c)에도 쓴다. 메인라인 jam table과 겹치는지는 미확인이다.
- 부트코드가 스위치를 먼저 초기화한다 → 리눅스 진입 시 8367이 이미 설정되어 있을 수 있다. 1차 initramfs 단계에서는 이 상태를 그대로 이용할 수 있다.
- 포트 매핑(순정 명세): WAN=4, LAN1~4=0~3.

## 7. 전제 조건 (conduit 쪽)

- 메인라인에는 97F 이더넷 드라이버가 없다.
  98C용 6.18 신규 드라이버(undisputed-seraphim 포크)를 리틀엔디언으로 바꾸고 P0 RGMII 초기화(`init_8197f_p0`)를 더한 최소 conduit MAC이 먼저 필요하다.
- OpenWrt 포럼 "Working Realtek SoC RTL8196E 97D 97F in last master"의 realtek 타깃(gaspare 브랜치, plappermaul 98C 6.12 포크):
  GPIO, IRQ, 타이머, PCI는 동작한다. 이더넷/스위치와 무선은 미완이다.
- 레지스터 시퀀스 정답지: 8devices `openwrt-8devices` 18.06 rtkmipsel 3.18 브랜치(RTL8197FS 벤더 드라이버).

## 8. 1차(유선 전용) 작업 범위

| 단계 | 내용 | 기존 자산 | 상태 |
|---|---|---|---|
| 1 | UART 접속, 부트로더(Realtek boot) 로그와 TFTP/메모리 로드 경로 확인 | `console=ttyS0,38400` | 미착수 |
| 2 | initramfs 부팅 (CPU, IRQ, 타이머, UART, SPI 플래시 읽기) | 포럼 realtek 타깃 97F 서브타깃 | 레퍼런스 있음 |
| 3 | DTS: 위 GPIO와 버튼/LED, 플래시 파티션 | §1 표 | 데이터 확보 |
| 4 | 97F P0 conduit MAC 최소 드라이버 | 98C 신규 드라이버 + 8devices 시퀀스 | **신규 작업 필요** |
| 5 | 8367 계열: 우선 부트코드 초기 상태로 태그 없이 단일 포트 통신 → 이후 DSA(rtl8365mb) 또는 VLAN 분리 | 메인라인 realtek-smi/rtl8365mb | 칩 판별 필요 |

## 9. RTL 칩 정리 (같은 SoC 계열 ipTIME 모델에서 나오는 칩)

| 칩 | 역할 | 쓰는 모델(예) | 순정 드라이버 | 메인라인 경로 |
|---|---|---|---|---|
| RTL8197F(H/N/NT) | SoC + 2.4GHz 11n 2x2 | 97F 계열 전부 | rtl819x NIC + rtl8192cd 내장 | SoC 기본(포럼 포크)만 있음. 이더넷/무선 없음 |
| RTL8367 계열 ("rtl8367r") | 외장 5+2포트 GbE 스위치 | 97F 계열 전부 | Realtek Switch API v1.4 (8367C/8367D/8370B 판별) | rtl8365mb: 0x6367 계열만 |
| RTL8812FR | 5GHz 11ac 2x2 PCIe | A2004SE, A2004SR, A2002SR, A604SE/SR 등 | rtl8192cd (WLAN_HAL_88XX) | **없음**, 계획 없음 |
| RTL8812BR | 5GHz 11ac 2x2 PCIe (8822B AP 변종) | A2004MU, A2003NS-MU, A2004NS-MU | rtl8192cd | rtw88 rtw8822be (10ec:b822) 가능성. ID 확인 필요 |
| RTL8832BR | 5GHz 11ax AX1200 2x2 PCIe (8852B 계열 AP용) | AX2004T, AX1500SR | rtk_wifi6.ko (PHL/g6, 커널 4.4) | rtw89 rtw8852b 대상이지만 AP 변종 ID와 AP 모드 동작 미확인 |
